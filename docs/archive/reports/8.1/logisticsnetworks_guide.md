# Logistics Networks 가이드·표시 경로 검수

현재 1.13.0 JAR의 GuideME 영어 17페이지를 모두 번역했어요. 한국어 후보와 이전 프로젝트
번역은 없으므로 재사용은 0페이지, 신규 번역은 17페이지예요. 원본 스크린샷은 그대로 참조하고,
그림 설명·본문·표·목차와 제작법이 없을 때 표시할 문구까지 한국어로 작성했어요.

## 현재 표시 경로

- 페이지: `assets/logisticsnetworks/guides/logisticsnetworks/guide/_ko_kr/`.
- 가이드 등록: `assets/logisticsnetworks/guideme_guides/guide.json`.
- 등록 파일의 직접 표시 문구 2개만 `translate` 컴포넌트로 연결했어요. 현재 영어를 `fallback`에
  보존하므로 다른 언어에서 한국어가 강제로 표시되지 않아요. 기본 언어·첫 페이지·회색 서식은 유지해요.
- 일반 언어 원본 454키에 가이드 이름·설명 2키를 더해 최종 한국어 언어 파일은 456키예요.
  신규 한국어 436개, 기존 한국어 재사용 0개, 공식 명칭·단위 등 원문 유지 20개예요.
- GuideME 21.1.17의 `GuideBuilder`, `GuideReloadListener`에서 리소스 경로와 언어별 페이지
  로딩을 확인했어요. `GuideItemSettings`의 `ComponentSerialization.CODEC`는 이름·툴팁을
  컴포넌트로 읽어요. `RecipeCompiler`가 `fallbackText`를 읽는 것도 확인했어요.
- `ATagCompiler`가 `name` 속성을 `LytFlowAnchor`로 만드는 것을 확인했어요. 번역한 제목에도
  기존 `#filters`, `#clipboard-editor` 링크가 도착하도록 원래 앵커 두 개를 유지해요.
- 관련 로더·모드 클래스와 JAR 해시는 `working/logisticsnetworks/display_audit.json`에 묶었어요.
  새 보조 실행 코드는 추가하지 않았어요.

## 오래된 원문 설명을 현재 동작에 맞춘 부분

현재 영어 가이드 안에서도 설명이 서로 달라, 아래 부분은 설치된 코드를 읽고 교정했어요.
숫자 보존 검사의 예외는 첫 페이지의 채널 번호 한 곳뿐이며 검증기에 정확한 원문을 고정했어요.

| 원문의 설명 | 반영한 내용과 확인 근거 |
|---|---|
| 첫 페이지 채널 번호 1~9 | 0~8. `NodeScreen.drawChannelTabs`가 0부터 9 미만까지 반복하며 인덱스를 그대로 `String.valueOf`에 전달해요. 다른 가이드 페이지도 0~8이에요. |
| 상단 선택기에 업그레이드도 채널별이라고 설명 | 업그레이드는 노드 전체에 적용해요. 같은 원문의 업그레이드 페이지와 `NodeClipboardConfig.upgradeItems`가 노드 단위인 구조를 대조했어요. |
| 필터 6칸 때문에 노드 전체가 6가지 설정만 가진다고 설명 | 채널마다 독립된 6개 필터 설정을 가진다고 정리했어요. 채널별 설정과 노드 전체를 혼동하지 않게 했어요. |
| 붙여넣기·대량 설치 때 필터 아이템도 소모 | 필터는 가상 설정으로 복사하고 필요한 업그레이드 아이템을 소모해요. `NodeClipboardConfig.buildUpgradeRequirements`와 현재 필터 페이지를 대조했어요. |
| 보관함이 꽉 차면 교체 아이템이 바닥에 떨어진다고 설명 | 먼저 반환 공간을 검사하고 부족하면 시작하지 않아요. `canFitReturnedItemsAfterConsumption`이 거짓이면 `INVENTORY_FULL`을 반환하는 경로를 확인했어요. |
| 클립보드 편집기의 필터를 실제 아이템처럼 회수한다고 설명 | 가상 필터 설정 편집·지우기로 안내해요. 현재 필터 페이지와 `NodeClipboardConfig`의 필터 데이터 복사 경로에 맞췄어요. |
| 화로 위쪽이 연료, 앞면이 제련 아이템이라고 설명 | 위쪽은 제련 입력, 옆면은 연료, 아래쪽은 결과물로 교정했어요. 설치된 Minecraft 1.21.1 SRG JAR의 `AbstractFurnaceBlockEntity`에서 `SLOTS_FOR_UP=[0]`, `SLOTS_FOR_SIDES=[1]`, `SLOTS_FOR_DOWN=[2,1]`과 면 선택을 읽어 확인했어요. 아래쪽의 빈 연료 용기 회수는 이 원문의 간단한 예시 범위에 추가하지 않았어요. |

## 퀘스트·KubeJS와 검증

FTB Quests 파일 1,000개(현재 구조 66챕터), KubeJS 파일 871개를 읽었고 관련 모드명·네임스페이스·
물류 노드 참조는 0개예요. 관련 퀘스트 제목·Task·자동 제목·custom_name·직접 표시 문구의 수정 대상이
없어서 overrides는 바꾸지 않았어요. 조사 대상 전체 파일의 해시를 기록하고 재검증해요.

17페이지의 현재 JAR 원문·작업본·배포본·검수 해시, YAML 구조·제목, 태그·제작법·아이콘·이미지,
링크·앵커, 인라인 코드, 숫자·자리표시자·개행·이스케이프를 검사했어요. 영어 문단 후보는 없어요.
앵커 두 개와 검수한 `fallbackText` 두 개만 표시 경로에 맞춰 따로 검증해요.
실제 인스턴스 6,345개 파일의 경로·크기·수정 시각이 조사 전과 같아요.

실제 게임의 화면 폭, 그림과 번역 버튼의 대응, 가이드 클릭 이동은 아직 실행해서 확인하지 않았어요.
그림에 포함된 영어는 원본 이미지이며 이번 텍스트 번역 범위에 포함하지 않아요.
