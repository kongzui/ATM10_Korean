영어 원문과 대조해 문제 있는 번역만 고친 **수정본 JSON**을 만든다. 산출물 반영, 게임 적용, 커밋은
오케스트레이터가 하므로 하지 않는다.

- Python을 실행할 때는 항상 `PYTHONIOENCODING=utf-8`을 붙인다.

## 1. 시작 전에 반드시 읽기

1. `AGENTS.md`의 `번역 작업 원칙`부터 `고유명사와 전문용어`까지
2. `glossary/README.md` 전체(결정 기준, 이름 짓기 순서, 용어 적용 범위, 확정 용어, 6장 교체 대상)

용어집 확정 표기가 최우선이다. 자주 틀리는 기준: 엔티티(개체 X), 쿨타임(재사용 대기시간 X), 몹이
나타나는 뜻의 스폰(생성 X, 단 `생성 알`·`몬스터 생성기`·광석 생성은 유지), 생물 군계, 단축 바,
키 지정, 리스폰, 설정(옵션 X), 문장 속 동작은 순간이동.

## 2. 입력 파일

`temp/rereview/<계열>/`의 대조 파일이다. 언어는 `<네임스페이스>.txt`, 퀘스트는
`chapters__<챕터>.txt`처럼 경로의 `/`를 `__`로 바꾼 이름이다. 키마다 세 줄이다.

```
키
  EN[출처]: "영어 원문(JSON 표기)"
  KO: "현재 한국어(JSON 표기)"
```

- `EN[JAR]`은 해당 모드 영어, `EN[다른 JAR(ns)]`는 다른 모드가 넣은 영어, `EN[영어 원문 없음]`은
  원문 파일이 없다는 뜻이다. 원문이 없으면 키의 ID가 사실상 원문인지 먼저 본다(구조물 이름 등).
- 퀘스트 값은 문단 목록(JSON 배열)일 수 있다. 수정본도 같은 자료형과 같은 문단 수로 쓴다.
- `\n`은 줄바꿈, `\\n`은 글자 그대로의 역슬래시 n이다.
- **모든 키를 끝까지 읽는다.** Read의 offset/limit로 약 600줄(200키)씩 나눠 읽고 건너뛰지 않는다.

## 3. 판단 기준

**문제없는 번역은 바꾸지 않는다.** 취향 차이, 같은 뜻의 다른 표현, 사소한 어순은 수정 사유가
아니다. 아래 경우에만 고친다.

| 유형 | 예 |
|---|---|
| 오역 | 뜻이 틀림, 정보·숫자·조건 누락이나 추가 |
| 번역투 | `당신`, `그것`, `이는`, `이러한`, `~할 것입니다`, `~에 의해`, `~을 위한`, `~된 경우`, `이 옵션을 선택하면`, 영어 어순 그대로라 어색한 문장 |
| 용어집 | 확정 표기와 다름, 공식 모드명 음역·뜻 번역 |
| 이름 불일치 | 아이템·블록·구조물·설정 이름이 게임 속 확정 이름과 다름 |
| 말투 | 문장인데 합쇼체(`~합니다`, `~하세요`)가 아님, 안내문인데 `~합니다`로 끝남, 버튼·설정 이름인데 문장으로 씀 |
| 형식 | 자리표시자(`%s`, `%1$s`, `{0}`), `§`·`&` 서식 코드, `\n` 개수가 원문과 다름 |

- 설정 설명의 `If true`/`If false`는 `켜면`/`끄면`처럼 쓴다.
- 과한 의역 금지: 원문에 없는 정보·농담을 넣지 않고 기능 이름을 새로 짓지 않는다.
- 문장에서 확정 용어를 매번 되풀이하지 않아도 된다. 같은 대상을 다른 동의어로만 부르지 않는다.
- 명령 결과·오류 메시지는 완결된 문장으로 쓴다(`~했습니다`). `초기화: %s 님`처럼 줄이지 않는다.
- 같은 모드 안에서 같은 영어가 여러 한국어로 섞여 있으면 다수 표기나 용어집 표기로 맞춘다.

## 5. 결과물(이 파일들만 쓴다)

1. 수정본(고친 키만, 고친 게 없으면 만들지 않음)
   - 언어: `working/quality_rereview/<계열>/lang/<네임스페이스>.json` → `{"키": "새 값"}`
   - 퀘스트: `working/quality_rereview/<계열>/quests/<챕터 파일 이름>.json` → `{"키": 새 값}`
     (현재 KO와 같은 자료형·문단 수)
   - 이미 파일이 있으면 기존 항목을 지우지 말고 추가·수정한다.
   - UTF-8, 2칸 들여쓰기 JSON. 현재 KO 값을 복사해 고친다.
2. 메모: `temp/rereview/<계열>/notes_<파일 이름>.json`
   ```json
   {
     "changed": {"키": "유형: 한 줄 사유"},
     "uncertain": {"키": "무엇이 불확실해 고치지 않았는지"},
     "glossary_suggestions": ["반복되는데 용어집에 없는 용어 제안"]
   }
   ```

## 6. 끝내기 전 자가 점검

1. 내 수정본의 모든 값에 대해 자리표시자, 서식 코드, `\n` 개수를 원문과 다시 비교한다.
2. 내 범위 전체(유지한 키 포함)에서 3장 번역투 목록의 표현을 Grep으로 한 번 더 찾아 본다.
   자연스러운 쓰임(`보이는`, `덮어쓰이는` 등)은 그대로 둔다.
3. 검증을 실행해 `errors`에 **내 파일** 오류가 없게 한다.
   - 언어: `cd scripts && PYTHONIOENCODING=utf-8 python quality_rereview_lang.py <계열>`
   - 퀘스트: `cd scripts && PYTHONIOENCODING=utf-8 python quality_rereview_quests.py <계열>`
   - 다른 워커가 동시에 작업하므로 남의 파일 오류는 고치지 말고 최종 답변에만 적는다.
   - 이 명령이 `versions/8.1/reports/`의 보고 JSON을 새로 쓰는 것은 정상이다.
